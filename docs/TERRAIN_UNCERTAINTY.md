# Published terrain uncertainty and native return support

Implemented 15 November 2026. Both curated sites now support the nominal PGDA78 surface and published statistical clones 0001–0003 throughout mission assessment, native dynamics, replay, comparisons, bounded sweeps and repair audits. These are uncertainty cases, not additional measured surfaces or a calibrated mission-risk model.

## Scientific inputs and convention

NASA distributes 100 clones per site. Clavius selected the first three indices for each site before inspecting simulation outcomes. All eight new original TIFFs (six clone surfaces, two LDEC count maps) are pinned by URL, byte count, SHA-256 and native metadata in `public/data/simulation-manifest.json`. [NASA PGDA78 distribution](https://pgda.gsfc.nasa.gov/products/78).

The files named `*_0001_err.tif` etc. contain complete elevations, not additive offsets. Their values have the nominal height scale; clone-minus-nominal differences are metre-scale. This agrees with the construction in Barker et al., Figure 11 panel G and Section 4. The numerical projection parameters, dimensions, posting and pixel registration match the corresponding nominal surface, although the WKT labels differ. Each file is used directly as the height raster. A 20 m RMS difference gate checks the full-surface file convention; it is not an accuracy estimate. [Accepted manuscript](https://ntrs.nasa.gov/api/citations/20205009660/downloads/Mike%20Barker_%20Paper_%20Improved%20Lola.pdf).

All realizations retain the **nominal** site origin and ENU basis. Clone ground at the origin can therefore have nonzero local up. At Shackleton, clones 001/002/003 have origin up approximately −0.460449 / −0.576904 / −0.287598 m. Their slopes, route lengths, schedules, observer positions, local occluders, array incidence and physical contact meshes are recomputed from the selected full surface. A missing clone cell within the local region fails that case instead of using nominal regional terrain to fill it. PGDA90 regional terrain outside the local site remains nominal. The legacy observer-height RMS offset remains separately named and cannot be combined with a clone.

Only three of the published 100 surfaces per site are loaded. No complete tail bounds, regional terrain covariance, absolute accuracy determination, wheel-scale hazards or calibrated soil behavior follow from this subset. Clones are statistical reconstructions under the source model's assumptions. [Source and registration checks](validation/terrain-realization-sources.json).

## Return support and rendering

The nominal LDEC grids contain the number of LOLA returns in each 5 m native cell. Zero means an empty/interpolated nominal cell; positive values mean returns occur in that cell. Missing count evidence remains missing. Lookup uses the containing native cell, with no bilinear averaging of categories. A return somewhere in a cell does not measure every point in that cell or establish rover-scale clearance.

**LOLA support** maps a full 3,200 × 3,200 categorical image through the source polar coordinates, using nearest filtering and no mipmaps. Green marks cells with returns, gray marks empty/interpolated cells, amber marks unknown counts. Native-cell footprints remain distinct rather than spreading through blended vertex colors. Surface mesh geometry still interpolates the 5 m elevation grid; the image adds no measured terrain detail. The point inspector returns the native count independently of this display.

The two display derivatives are `public/data/lola-support/connecting-ridge.png` (1,010,931 bytes) and `shackleton-rim.png` (987,681 bytes). Exact source/output hashes, colors, row order and generation method are recorded under `terrain.support_derivatives`. Regenerate with `.venv/bin/python scripts/derive_lola_support.py`; source setup also verifies/regenerates them. Texture bytes are hash-checked before loading. An unavailable image or insufficient GPU texture size disables the layer while numerical counts remain available. Vite must be restarted after adding files under its ignored scientific-data directory, so its static-file catalogue includes the new images.

## Testing and independent audits

Default six-case sweeps balance seeded permutations of the selected source surface, nominal terrain and clone 001, with duplicate IDs removed, while independently drawing declared capacity, solar, mobility and speed assumptions. Explicit surface lists are supported. Missing scientific support is retained as an insufficient-evidence case, not substituted with nominal geometry or discarded from the count. Entire sweep exports now reproduce case inputs/outcomes and aggregate metrics, in addition to the individual replayable children.

Repair candidates keep the source mission's surface. By default the audit phase uses clones 002 and 003, excluding the source surface if it is one of those. Nominally supported candidates are frozen by cost before audit outcomes are examined. An explicit audit list cannot include the nominal-selection surface. Dedicated RNG namespaces and exact surface IDs are recorded. Hardware perturbations are generated independently of selection; the same audit terrain can recur across cases and is shared across candidates for comparison. These are held-out sensitivity cases, not independent physical worlds or success probabilities.

Exports retain the selected surface, full clone catalogue, fixed origin, raw asset identities and captured numerical implementation. Reproduction constructs its source catalogue from the captured record. Saved display checks also compare active surface, nominal origin and count-source hashes before replacing the terrain. Linked physical probes must match the source mission's site, robot and surface ID; synthetic flat benchmarks cannot claim a lunar clone.

## Executed evidence and remaining work

The suite passes **95 backend tests**, **7 global-terrain tests**, and the production build. New checks cover full-surface interpretation, fixed frames, native counts, missing-clone rejection, numerical horizon/slope changes, native MuJoCo contact, Gazebo packet/link identity, disjoint audit surfaces, unknown sweep cases and captured-source reproduction. An exhaustive pixel-class check verifies both display images against all native count cells and checks the polar-to-texture north/south orientation.

[Paired 12-hour missions](validation/terrain-realization-acceptance.json) fix robot, time, route offsets and science activity while changing only site/surface. At Connecting Ridge the maximum sampled route slope ranges from 4.429° (nominal) to 7.133° (clone 003). At Shackleton it ranges from 5.927° to 8.090°. At the Shackleton origin, the Sun horizon changes from −0.5099° nominal to 1.0189° in clone 001 and 2.7862° in clone 002. These are selected numerical sensitivities, not global error bounds.

The six-case Shackleton sweep recorded two violations and no unsupported cases. Its 791,193-byte export reproduces every case and aggregate metric. A reserve-failure repair search checked three candidates and audited two frozen candidates against three cases using 002/003; one candidate passed all cases. Its 1,288,292-byte export reproduces the candidate/audit outcomes. [Sweep reproduction](validation/terrain-clone-campaign-reproduction.json), [repair reproduction](validation/terrain-clone-repair-reproduction.json). Those records retain their captured implementation identities; later support-rendering changes do not rewrite them.

The local Gazebo worker has been rebuilt with explicit terrain-realization identities and passed its matching native analytical benchmark. [Runtime identity](validation/gazebo-terrain-realization-runtime.json). Additional browser/native segment evidence is recorded in `validation/terrain-realization-browser.json`. Contact force/count channels remain uninstrumented in Gazebo. Wider terrain ensembles, convergence across more geometries, observed-shadow validation, regional errors, calibrated wheel–soil/thermal response and the orbital/GMAT handoff remain unfinished.
